# kr-competitors

모든 고객은 이미 어떤 식으로든 그 문제를 해결하고 있다. 누가, 얼마에, 무엇이 불만인지를 **국내 출처**에서 찾아 추측 대신 근거에서 출발한다.

> 원작: [founder-competitors](https://github.com/Jakeschincariol/founder-skill) (MIT, Jake Schincariol). 한국 시장·광고 수익 모델에 맞춰 고쳤다.

---

## 0단계: 사업 유형을 먼저 정한다

경쟁자의 정의가 유형마다 다르다. **이걸 건너뛰면 엉뚱한 걸 조사한다.**

| 유형 | 경쟁자란 | 주로 볼 곳 |
|---|---|---|
| **오프라인 장사** | 같은 동네 같은 업종 | 네이버 플레이스, 카카오맵, 당근마켓 |
| **온라인 판매** | 같은 검색어의 상위 판매자 | 네이버쇼핑, 쿠팡, 스마트스토어, 다나와 |
| **광고 수익 콘텐츠** | 같은 키워드 **검색 상위 노출자** | 네이버 통합검색, 구글, 유튜브 |
| **리드·문의형** | 같은 검색어로 문의를 받는 곳 | 네이버 검색, 파워링크 |
| **비영리·위탁** | 같은 사업을 수탁한 기관 | 지자체 공고, 보조금24, 유사 기관 누리집 |

사용자가 말하지 않았으면 **묻는다.** 광고 수익 콘텐츠 사업에서 "경쟁자"는 같은 제품을 파는 회사가 아니라 **내가 노리는 검색어의 1페이지를 이미 차지한 문서**다.

## 규칙

- **공개 출처만, 사실마다 링크.** 못 닿은 출처는 못 닿았다고 적는다. 경쟁자·가격·별점·리뷰를 **절대 만들어내지 않는다.**
- **긁지 말고 읽는다.** 사람이 보듯 본다. 각 사이트 약관을 존중한다.
- **인용은 원문 그대로**, 짧게, 링크와 함께. 이건 조사 자료이고 추천사가 아니다.
- 확인 안 된 것은 빈칸으로 두지 말고 **"확인 못 함"** 이라고 적는다.

### 한국 출처를 읽을 때의 함정 — 반드시 지킨다

- **네이버 플레이스 리뷰는 두 종류다.** `방문자 리뷰`와 `블로그 리뷰`. **블로그 리뷰는 상당수가 협찬·체험단**이라 불만이 걸러져 있다. → **방문자 리뷰를 먼저, 그리고 더 무겁게 본다.** 블로그 리뷰를 쓸 때는 "협찬 가능성 있음"을 표에 적는다.
- **별점 평균보다 분포와 개수**를 본다. 리뷰 12개에 4.9점은 신호가 아니다.
- **네이버쇼핑 최저가는 실구매가가 아닐 수 있다.** 배송비·옵션가·쿠폰을 분리해 적는다.
- **상위 블로그가 곧 강자는 아니다.** 체험단 대량 발행으로 올라온 경우가 있다. 발행 주기와 주제 일관성을 같이 본다.
- 카페·지식iN은 **수요(무엇을 궁금해하나)** 를 보는 데는 좋고, **사실 근거로는 쓰지 않는다.**

## 1단계: 누가 있나

| 분류 | 뜻 | 예 (반려견 산책 지도 사이트) |
|---|---|---|
| 직접 | 같은 고객에게 같은 것 | 댕댕이맵, 댕댕맵 같은 반려견 동반 지도 |
| 간접 | 같은 일을 다른 방식으로 | 네이버 플레이스 "애견동반" 검색, 블로그 후기 |
| 대체재 | 사업 없이 해결하는 방법 | 공공데이터포털 원본을 직접 받아 보기, 맘카페 질문 |

직접·간접 **5~10개** + 주요 대체재. 오프라인이면 지도에서 정확한 반경으로, 온라인이면 **고객이 실제로 치는 말**로 검색한다 (`"강남 애견동반 카페"`, `"<제품> 추천"`, `"<제품> 단점"`).

**광고 수익 콘텐츠 사업이면 이렇게 한다:**

**1-a. 먼저 수집 수단이 있는지 확인한다 — 건너뛰면 1단계가 중간에 멈춘다**

| 검색 환경 | 어떻게 |
|---|---|
| 네이버·구글 코리아에 직접 접근 가능 | 그대로 검색한다 (가장 정확) |
| **클라우드 세션 등 접근 제한** | 쓸 수 있는 검색 도구로 하되 **그 도구 이름을 기록**한다. 국외 기반 도구는 **순위가 국내 실제 순위와 다르다** — "경쟁자 존재의 증거"로만 쓰고 **순위는 신뢰하지 않는다** |
| 아무 검색도 안 됨 | **운영자에게 넘긴다.** 검색어 목록과 "각 검색어를 네이버·구글에서 검색해 1페이지를 캡처해 달라"는 요청을 적고 멈춘다. 추정으로 채우지 않는다 |

**1-b. 노리는 검색어 10~20개 — 출처 우선순위를 지킨다**

| 순위 | 출처 | 왜 |
|---|---|---|
| 1 | **Search Console·네이버 서치어드바이저의 실제 유입 검색어** | 추측이 아닌 실측. 이미 노출되는 검색어가 가장 싸게 올릴 수 있는 것 |
| 2 | **사이트 자신의 `<title>`·`<h1>` 역추출** | 사이트맵을 돌며 제목을 모으면 "이 사이트가 노리는 검색어"가 나온다. 접근 권한 없이 가능 |
| 3 | 네이버 자동완성·연관검색어 | 접근 가능할 때만 |

1·3이 없으면 **2로 진행한다.** 멈추지 말고, 무엇으로 뽑았는지 적는다.

**1-c. 1페이지에 뜬 것을 전부 적는다**

네이버면 노출 영역까지 (블로그·카페·지식iN·웹사이트·인플루언서·플레이스·동영상).

그리고 **콘텐츠 SERP의 경쟁자는 아래 네 유형으로 분류한다.** 유형마다 대응이 완전히 다르다:

| 유형 | 예 | 대응 |
|---|---|---|
| **도구·계산기 사이트** | `계산기` 전문 사이트 | **진짜 경쟁자.** 같은 수요를 같은 방식으로 먹는다. 이기려면 더 정확·더 쉬워야 |
| **블로그·정보 사이트** | 개인 블로그, 정보 블로그 | 경쟁 가능. 최신성·출처 밀도로 이긴다 |
| **공공기관** (`.go.kr`·`.or.kr`) | 복지로, 공단, 지자체 | **포기 후보.** 아래 판정 |
| **언론** | 신문·방송 기사 | **뚫을 수 없다.** 도메인 권위가 다르다. 그 검색어는 머리 키워드를 피하고 롱테일로 우회 |

**1-d. 공공기관 점유 판정**

`.go.kr`·`.or.kr` 공공기관이 상위를 먹고 있으면 **그 검색어는 포기 후보**다. 민간이 머리 키워드로 정부 포털을 뚫는 건 비현실적이다.

단, 포기의 단위는 **검색어이지 주제가 아니다.** 같은 주제의 롱테일로 우회한다:

| 공공기관이 먹은 검색어 | 우회 가능한 롱테일 |
|---|---|
| "문화누리카드 사용처" (지자체 공고) | "문화누리카드 온라인 서점 되나", "문화누리카드 잔액 조회" |
| "기초연금 모의계산" (복지로·공단) | "월 소득 150만원 기초연금 얼마", "집만 있으면 기초연금" |

**판정 기준**: 1페이지 10개 중 공공기관·언론이 **5개 이상이면 머리 키워드는 포기**, 롱테일로 간다.

## 2단계: 사실 수집

`research/competitors.csv` 한 줄에 한 경쟁자:

```
name,type,url,channel,price_or_free,what_it_sells,positioning_line,rating,review_count,visitor_review_count,blog_review_count,sponsored_risk,source_date
```

- `positioning_line`: 그들이 스스로 쓴 제목·슬로건을 **그대로 복사**
- `price_or_free`: 비교 가능한 품목 기준. 포함 항목(배송비·옵션)을 괄호로
- `visitor_review_count` / `blog_review_count`: **분리해서** 적는다
- `sponsored_risk`: 협찬 의심 근거가 있으면 `높음/중간/낮음`

**콘텐츠 사업이면 대신 `research/serp.csv`:**
```
keyword,engine,source_tool,rank_reliable,rank,area,owner_type,owner,url,doc_type,published_at,source_date
```
- `engine`: naver / google
- **`source_tool`**: 무엇으로 봤나 — `직접검색` / 도구 이름. 생략하면 나중에 이 데이터를 믿을 수 없게 된다
- **`rank_reliable`**: `Y` (국내에서 직접 검색) / `N` (국외 기반 도구 — 순위는 참고치, 존재 여부만 유효)
- `area`: 네이버 노출 영역 (블로그/카페/웹사이트/지식iN/인플루언서/동영상)
- **`owner_type`**: `도구` / `블로그` / `공공기관` / `언론` / `기업` — 1-c의 네 유형. 대응 전략이 여기서 갈린다
- `owner`: 운영 주체 이름

## 3단계: 고객이 뭐라고 하나

상위 3~5곳의 리뷰를 읽는다. **1~3점을 먼저**, 그다음 "좋은데 ~만 아쉽다" 식 4점.

- 반복되는 불만을 **주제별로 묶고 건수를 센다**
- 주제마다 원문 인용 1~2개 + 링크
- **3건 미만이면 "근거 얇음"으로 표시**한다
- 네이버 방문자 리뷰 / 카카오맵 / 구글맵 / 앱스토어 리뷰를 **출처별로 나눠** 센다

콘텐츠 사업이면: 상위 문서의 **댓글**과 해당 주제 지식iN·카페 질문에서 "아직 아무도 제대로 답 안 한 질문"을 찾는다. 그게 빈자리다.

## 4단계: 지도와 빈자리

`research/competitors.md`:

1. **표** (CSV에서), 직접 경쟁 순으로
2. **가격대**: 최저·중위·최고 (비교 품목 기준). 무료 서비스면 "무료 — 수익모델: 광고/제휴/없음"
3. **포지셔닝 지도** (글로): 이 고객에게 실제로 중요한 두 축을 골라 각 경쟁자를 배치
4. **불만 순위** + 링크 + 출처별 건수
5. **빈자리**: 아무도 제대로 못 하는 것, 근거와 함께. **빈자리가 없으면 없다고 분명히 쓴다.** 그게 이 스킬이 줄 수 있는 가장 쓸모 있는 결과다
6. **위협**: 누가 가장 빨리 따라올 수 있나, 어떻게

### 한국 시장에서 꼭 확인할 항목

- **공공데이터를 쓰는 사업이면**: 경쟁자도 같은 데이터를 쓰고 있나? (공공데이터포털 같은 데이터셋이면 **중복 콘텐츠**로 검색에서 불이익을 받는다) → 차별화는 ⓐ 최신성 검증 ⓑ 원본에 없는 정보 ⓒ 경쟁자가 약한 카테고리
- **상호·브랜드명 충돌**: 같은·비슷한 이름이 있나 (→ `/kr-brand` 로 넘긴다)
- **지자체·공공기관이 같은 걸 무료로 하고 있나** — 이걸 놓치면 사업 전체가 무너진다

## 산출물

**조사 대상 사업의 작업 폴더 기준**으로 `research/` 아래에 쓴다. 조사 대상과 지금 열려 있는 저장소가 다르면 (예: 스킬은 A 저장소에 있고 조사 대상은 B 프로젝트) **어디에 쓸지 먼저 확인한다.** 엉뚱한 저장소에 커밋하지 않는다.

- `research/competitors.csv` (또는 콘텐츠 사업이면 `research/serp.csv`)
- `research/competitors.md`

다음: `/kr-marketing` 이 불만과 빈자리를 메시지로, 가격대를 포지셔닝으로 쓴다.

**단독으로 돈다.** 다른 스킬의 출력이 없어도 된다. 없으면 없는 대로 진행하고, 무엇이 없어서 무엇을 추정했는지 적는다.

### 보고할 때 반드시 밝힐 것

- 검색을 **무엇으로** 했나, 그 도구의 순위를 믿을 수 있나 (`rank_reliable`)
- 못 본 출처 (네이버 미접근 등)
- 그래서 어떤 결론이 **"존재 확인"** 이고 어떤 것이 **"순위 추정"** 인가
