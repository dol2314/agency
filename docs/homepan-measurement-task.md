## 0. 이 세션에게

지금 `state/title_test.csv` 에 제목과 조회수가 쌓이고 있다. 그런데 **홈판 노출 자체는 기록되지 않는다.**

전체 운영이 홈판 노출을 겨냥하는데 측정하는 것은 조회수다. **조회수는 홈판 노출의 결과이지 홈판 노출 여부가 아니다.** 그래서 지금 `도구/title_report.py` 는 "어떤 제목이 조회수가 높은가"까지만 답할 수 있고, **"어떤 제목이 홈판에 뜨는가"는 답할 수 없다.** 그 칸을 채우는 것이 이 작업이다.

### 규칙

- **이미 발행된 글을 수정·삭제하지 않는다.** 이 작업은 CSV 기록과 분석 도구만 건드린다. 글은 손대지 않는다
- **추측으로 칸을 채우지 않는다.** 확인 못 한 것은 `unknown` 으로 남기고 보고한다
- 네이버 아이디·비밀번호를 대신 입력하지 않는다
- 기존 `title_test.csv` 의 칸과 행은 **지우거나 순서를 바꾸지 않는다.** 칸만 뒤에 덧붙인다
- 작업 전에 `state/title_test.csv` 를 **백업**한다 (`state/title_test.csv.bak-YYYYMMDD`)

## 1단계: 현황 파악 — 추측하기 전에 읽는다

아래를 먼저 확인하고 **결과를 보고한 뒤** 2단계로 간다.

```powershell
# 현재 칸 구성과 행 수
Get-Content state\title_test.csv -First 3
(Get-Content state\title_test.csv).Count

# 조회수가 어떻게 들어오고 있는지
Select-String -Path 도구\title_report.py -Pattern "view|조회|csv|column" -Context 1,1
```

보고할 것:
1. `title_test.csv` 의 **현재 칸 목록**과 행 수
2. 조회수는 **누가 언제 채우는가** — 수동인가, 스크립트인가, 어느 시점인가
3. `title_report.py` 가 지금 **무엇을 집계**하는가

## 2단계: 홈판 노출을 무엇으로 판정할지 정한다 ★ 가장 중요

**이 단계를 건너뛰고 칸만 만들면 쓸모없는 칸이 된다.**

네이버 블로그 통계에 들어가 **유입 경로 분류의 실제 라벨을 눈으로 확인**하라. 내(지시서 작성자) 기억으로 라벨명을 단정하지 않는다.

```
블로그 관리 → 통계 → 방문 분석 / 유입 분석
```

확인할 것:

| 질문 | 왜 |
|---|---|
| 유입 경로가 어떤 항목으로 나뉘는가 (정확한 라벨 그대로 적어라) | 홈판 유입이 별도 항목으로 잡히는지가 이 작업의 전제 |
| **검색 유입과 블로그 내부 유입이 구분되는가** | 구분되면 경로 B(자동)가 가능 |
| 글 단위로 유입 경로를 볼 수 있는가, 블로그 전체만 되는가 | 글 단위가 안 되면 경로 A로 가야 한다 |
| 과거 날짜를 소급해 볼 수 있는가, 며칠까지 | 발행 후 N일에 되돌아가 채울 수 있는지 |

그 결과로 **둘 중 하나를 고른다. 어느 쪽을 골랐는지와 근거를 보고하라.**

### 경로 B — 유입 경로로 추론 (가능하면 이쪽)

글 단위로 "검색이 아닌 블로그 내부 유입"을 볼 수 있으면, 그 수치로 홈판 노출을 추론한다.

- **기준선을 먼저 만들어야 한다.** 지금은 비교 대상이 없다
- **2주간 그냥 수집만 한다.** 판정하지 말고 숫자만 쌓는다
- 2주 뒤 그 블로그의 중위값을 구하고, "중위값의 몇 배 이상이면 홈판 노출로 본다"를 정한다
- 그 임계값을 `state/homepan_threshold.json` 에 **기준일과 함께** 적어 둔다

> 이건 **추론이고 직접 관측이 아니다.** CSV에 그렇게 표시한다 (`method=inflow`).

### 경로 A — 직접 관측 (경로 B가 불가능하면)

홈판·주제판을 **직접 열어** 자기 글이 있는지 본다.

- 하루 **한 번 고정된 시각**에 확인한다 (시각을 정해 적어 둔다. 시점이 흔들리면 데이터가 못 쓰게 된다)
- 발행 후 **D+1, D+3, D+7** 세 번 확인한다. 홈판 노출은 발행 직후가 아닐 수 있다
- 봤으면 **어느 주제판인지**까지 적는다
- 못 봤으면 `N` 이 아니라 **`not_seen`** 이다 — 안 뜬 것과 내가 못 본 것은 다르다

> 이쪽은 노동이 든다. 블로그 3개 × 하루 7편이면 부담이 크니, **블로그3만 4주 먼저** 해서 경로 B의 임계값을 보정하는 데 쓰는 것을 권한다.

## 3단계: CSV 칸 추가

`state/title_test.csv` **맨 뒤에** 아래 칸을 덧붙인다. 기존 칸은 건드리지 않는다.

| 칸 | 값 | 설명 |
|---|---|---|
| `views_d3` | 정수 / 빈칸 | 발행 후 3일 조회수 — **비교 시점을 고정**하기 위한 칸 |
| `views_d7` | 정수 / 빈칸 | 발행 후 7일 조회수 |
| `inflow_search_d7` | 정수 / 빈칸 | D+7까지 검색 유입 |
| `inflow_internal_d7` | 정수 / 빈칸 | D+7까지 블로그 내부 유입 (경로 B의 근거) |
| **`homepan`** | `Y` / `N` / `not_seen` / `unknown` | 핵심 칸 |
| `homepan_section` | 주제판 이름 / 빈칸 | 떴다면 어디에 |
| `homepan_first_seen` | `YYYY-MM-DD HH:MM` / 빈칸 | 처음 본 시점 |
| `homepan_method` | `observed` / `inflow` | 직접 봤나, 유입으로 추론했나 |
| `homepan_checked_at` | `YYYY-MM-DD` | 확인한 날 — **비어 있으면 아직 안 본 글** |

**`homepan` 값의 뜻을 혼동하지 마라:**

- `Y` — 홈판에서 봤다 (또는 임계값 초과)
- `N` — D+7까지 확인했고 안 떴다고 판단한다
- `not_seen` — 확인은 했지만 못 봤다. 안 떴다고 단정할 수 없다
- `unknown` — 확인 못 했다

> **`N` 과 `not_seen` 을 섞으면 분석이 전부 틀어진다.** 경로 A에서는 기본값이 `not_seen` 이다. `N` 은 D+1·D+3·D+7 세 번 다 확인한 뒤에만 쓴다.

### 기존 행 처리

이미 쌓인 행은 **소급하지 않는다.** 새 칸은 빈칸 또는 `unknown` 으로 둔다. 통계 소급 조회가 되는 범위 안에서만, 운영자가 요청하면 채운다. **지어내서 채우지 않는다.**

## 4단계: 채우는 루틴

발행 시점과 결과 수집 시점이 다르다. **두 개로 나눈다.**

### 4-1. 발행 시 (기존 흐름에 추가)

`build_post.py` 또는 발행 스크립트가 행을 만들 때, 새 칸을 **빈칸으로** 생성한다. `homepan_checked_at` 은 비워 둔다 — 그게 "아직 안 본 글" 표시다.

### 4-2. 수집 루틴 (새로 만든다)

`도구/collect_homepan.py` (또는 PowerShell):

```
1. title_test.csv 에서 homepan_checked_at 이 빈 행을 찾는다
2. 그중 발행 후 3일·7일이 지난 글을 고른다
3. 경로 B면: 블로그 통계에서 그 글의 유입 경로 수치를 읽어 채운다
   경로 A면: 확인할 글 목록을 출력하고, 운영자가 본 결과를 입력받는다
4. homepan_checked_at 에 오늘 날짜를 적는다
```

**하루 한 번** 돌린다. 기존 새벽 자동 루틴에 붙이면 된다.

> 통계 화면을 자동으로 읽는 것이 막히면 **자동화를 억지로 밀지 마라.** 확인할 글 목록만 출력하고 입력은 사람이 하는 쪽으로 간다. 경로 A는 원래 그렇게 돌아간다.

## 5단계: `title_report.py` 확장

지금은 클릭 이유별 조회수를 비교한다. **홈판 노출률을 추가한다.**

출력에 넣을 것:

```
클릭 이유별
  이유 | 글 수 | 홈판 Y | 홈판률 | views_d7 중위 | 검색유입 중위
  손해 보기 싫다 |  12 |  3 | 25% | ... | ...
  동년배         |   9 |  1 | 11% | ... | ...
  ...

제목 종류별 (홈판형 / 검색형)
  → 홈판형이 실제로 홈판에 더 뜨는가. 안 뜨면 v4 규칙의 전제가 틀렸다
```

**판정 규칙을 코드에 박아라:**

- `homepan_checked_at` 이 빈 행은 **집계에서 제외**한다 (아직 결과가 없는 글)
- `not_seen` 은 `N` 과 **따로 센다.** 합치지 않는다
- **글 수가 5편 미만인 클릭 이유는 "근거 얇음"으로 표시**하고 비율을 강조하지 않는다
- `homepan_method` 가 섞여 있으면 **`observed` 와 `inflow` 를 나눠 보여준다.** 추론과 관측을 한 숫자로 합치지 않는다

## 7. 2주 뒤에 답해야 하는 질문

이 측정이 돌기 시작하면 아래를 답할 수 있어야 한다. 지금은 못 답한다.

1. **홈판형 제목이 실제로 홈판에 더 뜨는가** — 안 뜨면 v4 규칙의 전제가 틀렸다
2. 클릭 이유 7가지 중 **홈판에 잘 뜨는 것과 조회수만 높은 것**이 갈리는가
3. 하루 7편 중 홈판에 뜨는 것은 몇 편인가 — **발행량을 늘리는 것이 답인지 판정**한다
4. 대표사진 교체가 홈판 노출을 바꾸는가 (*"썸네일이 제일 중요하다"* 를 숫자로 검증)

## 8. 이 지시서가 모르는 것

- **`title_test.csv` 의 현재 칸 구성을 모른다.** 그래서 1단계가 정찰이다
- **네이버 블로그 통계의 유입 경로 라벨을 확신하지 못한다.** 홈판 유입이 별도 항목으로 잡히는지조차 확인이 필요하다 → 2단계에서 **눈으로 보고** 결정한다
- 네이버는 홈판 선정 기준을 공개하지 않는다. 이 측정은 **상관관계만** 보여준다. "이 제목이 홈판을 만든다"가 아니라 "이 제목인 글이 홈판에 더 자주 보였다"까지다
- 블로그1·2에도 같은 작업이 필요하지만, **블로그3만 먼저** 하는 것을 권한다. 측정 방법이 검증된 뒤 옮기는 게 싸다
