## 0. 결론 (먼저 읽을 5줄)

1. **새 사이트를 만들지 않는다.** bokjicard.co.kr을 "복지·고용 돈 계산소"로 넓힌다. 도메인 나이와 이미 만든 계산기 8종이 자산이고, 새 도메인은 승인과 색인을 처음부터 다시 해야 한다.
2. **잘될 콘텐츠는 "직접 입력해야 답이 나오는 2027년 기준 계산기 + 그 계산을 풀어 쓴 예시 글"이다.** 1월은 기준이 한꺼번에 바뀌는 달이라(중위소득 6.7% 인상, 최저임금 10,700원) 지금(11월)부터 만들면 첫 시즌을 잡을 수 있다.
3. **가장 차별화되는 신규 칸은 "장애인 고용" 계산기(고용부담금·장려금, 실업급여)다.** 기업 인사담당자가 찾는 주제라 광고 단가가 높고, 개인 사이트 경쟁자가 적고, 운영자의 현장 경력과 맞는다.
4. **앱은 돈을 직접 버는 수단이 아니라 재방문 장치다.** "내 복지 신청 기간 알림" 안드로이드 앱(로컬 알림 + 계산기 + AdMob)으로 만들어 검색 의존도를 낮춘다. 수익 기대치는 웹의 10~20% 수준으로 잡는다.
5. **dogmap부터 정리한다.** dogmap과 bokjicard는 같은 애드센스 계정을 쓴다. dogmap의 자동 생성 페이지 3,322개 중 얇은 페이지가 스팸·저가치 판정을 받으면 bokjicard 수익까지 같이 위험해진다.

- 기업용: 장애인 고용부담금 계산기, 고용장려금 계산기, "우리 회사 의무고용 인원" 계산기 (상시근로자 수 → 의무 인원, 미달 인원, 예상 부담금)
- 개인용: 실업급여 계산기(2027), 장애인 근로자 근로지원인·출퇴근 지원 안내, 장애인 취업 후 복지 변화(수급 자격이 어떻게 달라지나)
- 시즌: 고용부담금 신고·납부는 매년 1월 말 (공식 일정 재확인). 12월 중순 공개가 목표.

**클러스터 C. "상반기 신청 시즌" (3~5월 준비)**
- 근로장려금·자녀장려금 계산기 (5월 정기신청 전, 4월 중순 공개)
- 문화누리카드 2027 (2월 신청 시작 전), 에너지바우처 2027 (6월 전)

### 3-4. 페이지 하나가 갖춰야 할 것 (승인·스팸 방어 기준)

모든 계산기 페이지는 아래를 **전부** 갖춘다. 하나라도 빠지면 공개하지 않는다.

1. 계산기 (입력값은 브라우저 밖으로 보내지 않음)
2. 3줄 요약 (AI 브리핑·AI 개요가 인용하기 좋은 첫 문단)
3. **조건이 다른 계산 예시 3개 이상** (예: 1인 어르신 / 맞벌이 4인 / 장애인 1명 포함 3인) — 페이지마다 고유한 숫자
4. 기준표 (연도·가구원 수별 금액) + **기준일 + 공식 출처 링크**
5. 자주 막히는 질문 FAQ 5개 이상 (현장 질문 기반)
6. "다음에 할 일": 신청 방법, 가까운 행정복지센터, 관련 계산기 2~3개
7. 면책 문구 ("모의계산이며 실제 결과는 기관 심사로 결정")
8. 작성자·검수일 (about 페이지의 운영자 실명·경력과 연결)

예시 글(`/tips/`)은 "계산 예시 글" 형식으로 쓴다. 한 글 = 한 가지 실제 상황 + 계산기 결과 캡처/표 + 그 상황에서만 생기는 주의점. 지역명·숫자만 바꾼 복제 글은 쓰지 않는다.

- 이유: (1) 공식 예시 값으로 단위 테스트를 걸어 YMYL 오류를 막는다. (2) 같은 코드를 앱에서 그대로 쓴다. (3) 1월 1일 연도 전환을 데이터 교체만으로 끝낸다.

## 5. 앱 기획 — "복지 알림" (가칭) 안드로이드 앱

### 5-1. 왜 앱인가

웹 계산기는 "필요할 때 한 번" 쓰고 끝난다. 앱은 **신청 기간이 오면 먼저 알려 주는 것**으로 돌아오게 만든다. 이 기능은 웹 푸시보다 앱 로컬 알림이 확실하고, 고령층에게는 "홈 화면 아이콘"이 북마크보다 낫다.

### 5-2. 핵심 기능 (MVP)

1. **내 조건 저장 (기기 안에만)**: 나이대, 가구원 수, 장애 여부, 소득 구간, 지역(시도). 서버로 보내지 않음.
2. **받을 수 있는 복지 목록**: 저장한 조건으로 클러스터 A·B 계산 엔진을 돌려 "가능성 높음/확인 필요"로 표시.
3. **신청 기간 알림**: 웹사이트가 공개하는 `/data/calendar-2027.json`(사업명, 신청 시작·마감, 대상, 공식 링크)을 받아 로컬 알림 예약 (시작 7일 전, 시작일, 마감 3일 전).
4. **계산기**: 웹과 같은 계산 엔진. 결과 화면에서 "자세한 설명 보기"는 웹 페이지로 연결(웹 트래픽 환류).
5. **오프라인 동작**: 기준 데이터를 앱에 포함, 온라인일 때 갱신.

### 5-3. 기술 선택

- **Capacitor + 웹 기술(React/Vite) + 공유 계산 엔진**으로 만든다. 로컬 알림(`@capacitor/local-notifications`), AdMob(`@capacitor-community/admob`).
- TWA(웹사이트를 그대로 감싸는 방식)는 쓰지 않는다. 앱만의 기능이 없으면 Play의 "최소 기능" 정책에 걸릴 수 있고, 알림·오프라인 같은 앱 이유가 약해진다.
- iOS는 안드로이드 성과(설치 1,000 이상) 확인 후 검토 (개발자 연 99달러).

### 5-4. 수익화 (AdMob)

- 배너: 목록·결과 화면 하단 1개.
- 네이티브 광고: 복지 목록 5개마다 1개, "광고" 표시 명확히.
- **하지 않는 것**: 앱 실행 직후 전면 광고, 뒤로 가기 전면 광고, 계산 결과를 광고 시청 뒤에 보여 주기.
- 기대치: 앱 단독 수익은 작다(월 수만 원대에서 시작). 앱의 진짜 가치는 재방문과 웹 유입이다.

### 5-5. Google Play 정책 체크

- **정부 정보 제공 앱 공시**: 정부 기관과 무관함을 설명란·앱 안에 명시하고, 정보의 공식 출처 URL을 표시.
- 개인정보처리방침 URL 필수, 데이터 보안 섹션에 "데이터 수집 없음(기기 내 저장)" 정확히 기재 (AdMob이 수집하는 광고 ID는 별도 기재).
- 2023-11 이후 만든 개인 개발자 계정은 프로덕션 출시 전 **비공개 테스트(테스터 12명 이상, 14일 연속)** 필요 — 테스터 모집이 일정상 가장 긴 작업이다.
- 타깃 API 레벨: 2026-08-31 이후 신규 앱·업데이트는 Android 16(API 36) 이상 대상 (출시 시점에 Play Console 공지로 재확인).

## 7. 수익 추정 (가정 명시)

공식: **월 수익 = 일 방문 × 방문당 PV × 30 × (페이지 RPM ÷ 1,000)**

가정: 방문당 PV 2.0 (결과 화면 "다음 할 일" 링크 효과), 페이지 RPM 보수 3,000원 / 기준 5,000원 / 낙관 7,000원 (복지·고용 주제, 신규 사이트 할인 반영). 1월·5월 시즌은 평소의 2~3배 트래픽.

|---|---|---|---|
| 2027-01 (시즌 첫 달) | 100 / 400 / 900 | 약 12만 원 | 신규 도메인이라 순위 불확실 |

| 2027-05 (장려금 시즌) | 300 / 1,000 / 2,000 | 약 30만 원 | 클러스터 C 공개가 전제 |
