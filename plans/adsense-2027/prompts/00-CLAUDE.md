# CLAUDE.md — bokjicard.co.kr 프로젝트 규칙

> 이 파일을 bokjicard 저장소 루트에 `CLAUDE.md`로 넣는다. 모든 Claude Code 세션이 자동으로 읽는다.

## 이 사이트
- bokjicard.co.kr: 복지카드·복지 자격·금액 계산 + 장애인 고용 계산기. 한국어, 1인 운영, 애드센스(웹)·AdMob(앱) 수익.
- 스택: Next.js App Router, Cloudflare 서빙. 계산 로직은 `lib/calc/`(순수 함수 + 연도별 데이터 JSON)에 둔다.
- 기획안: `docs/plan/README.md` (없으면 운영자에게 위치를 묻는다).

## 절대 규칙
1. **금액·기준·일정은 공식 출처로 확인한 값만 쓴다.** 허용 출처: 보건복지부, 복지로, 고용노동부, 고용24, 한국장애인고용공단, 국세청·홈택스, 한국에너지공단, 문화누리, 법제처 국가법령정보센터, 정부 보도자료(korea.kr). 블로그·뉴스는 "어디서 발표됐는지" 찾는 실마리로만 쓰고 숫자의 근거로 쓰지 않는다.
2. 공식 출처를 확인하지 못한 값은 코드에 `verified: false`와 `TODO(확인 필요)`로 표시하고, 그 값을 쓰는 페이지는 공개(사이트맵·내비게이션 노출)하지 않는다. 보고에 목록으로 남긴다.
3. 모든 금액 데이터에는 `source_url`, `source_name`, `effective_date`(기준일), `checked_at`(확인일)을 붙인다.
4. **사용자 입력(소득·재산·나이·장애 여부 등)은 브라우저 밖으로 보내지 않는다.** GA4에는 계산기 ID와 결과 구간만 보낸다. URL 쿼리에도 넣지 않는다.
5. **애드센스 정책**: 광고 클릭 유도 문구 금지, 광고를 버튼·메뉴처럼 보이게 배치 금지, 뒤로 가기 가로채기 금지, 결과를 광고 뒤에 숨기기 금지, 첫 화면에서 입력 폼을 광고가 가리지 않게.
6. **대량 생성 금지**: 지역명·숫자만 바꾼 페이지를 만들지 않는다. 새 페이지는 기획안 3-4절의 8개 항목을 모두 갖춰야 사이트맵에 넣는다. 한 번에 사이트맵에 추가하는 새 URL은 20개 이하.
7. URL 규칙: 영어 소문자·하이픈, 끝에 `/`. 연도는 URL에 넣지 않는다(예외 `/2027/` 같은 연도 허브). 기존 URL을 바꿀 땐 운영자 승인 + 301.
8. 문장: 쉬운 한국어, 한 문장 한 가지 내용. 어르신이 읽는다고 생각한다. "~할 수 있습니다" 남발 금지, 결론부터.

## 작업 방식
- 코드를 바꾸기 전에 관련 파일을 먼저 읽고 기존 패턴을 따른다.
- 계산 로직을 바꾸면 `lib/calc/__tests__/`의 테스트를 추가·갱신하고 실행한다. 테스트 기대값은 공식 자료의 예시·고시 금액에서 가져온다.
- 작업이 끝나면 빌드(`npm run build` 또는 저장소 스크립트)와 테스트를 실제로 실행하고 결과를 보고한다.
- Cloudflare 대시보드, 서치콘솔, 서치어드바이저, 애드센스·AdMob 콘솔, Play Console처럼 코드 밖의 일은 직접 하지 않고 **운영자가 따라 할 단계**를 적는다.
- 커밋은 작은 단위로, 메시지는 한국어로 "무엇을 왜". 운영자가 지정한 브랜치에만 푸시한다.
