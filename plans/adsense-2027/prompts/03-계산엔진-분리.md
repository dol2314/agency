# 프롬프트 03 — 계산 엔진 분리 + 2027 기준 데이터

## 목표
모든 계산기의 로직을 순수 함수 + 연도별 데이터로 분리하고 테스트를 건다. 웹과 앱이 같은 엔진을 쓰고, 1월 1일 연도 전환을 데이터 교체만으로 끝내기 위해서다.

## Claude Code에게
```
1. 현재 /calc/ 아래 계산기 8종(median-income, livelihood, medicaid, housing-benefit, basic-pension, disability-pension, activity-support, long-term-care)의 코드를 읽고, 계산 로직이 어디에 있는지·어떤 상수를 쓰는지 표로 정리하라.

2. 아래 구조로 옮겨라 (UI 동작은 바꾸지 않는다):
   lib/calc/
     data/2026.json, data/2027.json   # 연도별 기준값. 각 값에 {value, unit, source_name, source_url, effective_date, checked_at, verified}
     schema.ts                        # 데이터 타입 + 로드 시 검증(zod 등 저장소에 있는 것 우선)
     year.ts                          # 기준 연도 선택: 오늘 날짜(Asia/Seoul) 기준, 사용자가 토글로 바꿀 수 있게
     medianIncome.ts, basicPension.ts, ... # 순수 함수. 입력 → {결과, 근거 설명 배열}
     __tests__/                       # 계산기별 테스트
   UI 컴포넌트는 lib/calc 함수만 호출하게 바꾼다.

3. 2027 데이터를 채워라. 공식 출처로 확인되는 값만 verified:true.
   - 2027 기준중위소득(가구원 1~7인), 생계(32%)·의료(40%)·주거(48%)·교육(50%) 선정기준: 보건복지부 고시 또는 보도자료로 확인.
     (참고: 보도로는 4인 6,929,885원, 1인 2,736,042원, 인상률 6.7%. 이 숫자를 그대로 넣지 말고 공식 자료와 대조하라.)
   - 2027 주거급여 기준임대료, 기초연금 선정기준액·기준연금액, 장애인연금 기초급여액: 아직 발표 전이면 verified:false + "발표 예정" 표시.
4. 테스트: 공식 자료에 나온 예시(가구원 수별 선정기준 금액 등)를 기대값으로 계산기마다 최소 5개 케이스. 경계값(정확히 기준선, 1원 초과) 포함.
5. 페이지에 연도 토글(2026/2027)을 넣고, 2027-01-01 00:00 KST 이전엔 2026, 이후엔 2027이 기본이 되게 하라. 결과 영역에 "기준일·출처" 표시.
6. 빌드·테스트 실행 결과와, verified:false 값 목록을 보고하라.
```

## 완료 조건
- `lib/calc/` 구조 완성, 기존 8종 UI가 엔진을 통해 동작 (계산 결과가 분리 전과 같음을 테스트로 확인)
- 테스트 전부 통과 (출력 첨부)
- verified:false 목록이 보고됨
