# 프롬프트 04 — 클러스터 A: 2027 복지 자격·금액

## 목표
1월 시즌(기준 전환) 전에 2027 기준 계산기와 허브를 공개한다. 12월 6일까지 공개 목표.

## 전제
- 03 완료 (lib/calc 엔진 + 2027 데이터)
- 01의 `docs/keywords/priority.md`가 있으면 그 우선순위를 따른다.

## Claude Code에게
```
docs/plan/README.md 3-3절(클러스터 A)과 3-4절(페이지 필수 8항목), 4-1절(URL), 4-3절(광고 배치)을 읽어라.

1. /calc/median-income/ 을 "2027 기준중위소득 판정기"로 업그레이드:
   - 입력: 가구원 수, 월 소득(근로·사업·기타 구분은 선택), 재산은 "간단 모드/자세히 모드"
   - 결과: 기준중위소득 대비 %, 생계·의료·주거·교육급여 각각 "가능성 높음 / 경계 / 어려움" + 이유 한 줄
   - 결과 아래 "이 조건이면 같이 확인해 볼 것" 2~3개 (기초연금, 장애인연금, 문화누리카드, 에너지바우처 중 조건에 맞는 것)
   - 주의: 실제 수급은 소득인정액(재산 환산 포함) 심사라는 점을 결과 바로 위에 한 줄로 명시
2. /calc/basic-pension/, /calc/livelihood/, /calc/housing-benefit/, /calc/medicaid/, /calc/disability-pension/ 를 2027 데이터에 맞게 갱신. 발표 전 값은 "2026 기준 · 2027 발표 예정" 배지.
3. 모든 계산기 페이지에 3-4절의 8개 항목을 갖춰라. 특히:
   - 3줄 요약은 페이지 맨 위, 계산기 바로 앞
   - 계산 예시 3개 이상: 서로 다른 가구 상황(예: 1인 어르신 / 장애인 1명 포함 3인 / 맞벌이 4인). 숫자는 엔진으로 실제 계산해 넣는다(손으로 쓰지 마라).
   - FAQ 5개 이상, FAQPage 구조화 데이터는 화면에 보이는 FAQ와 같은 내용일 때만
4. /2027/ 허브 페이지 신설: "2027년 달라지는 복지" — 바뀐 기준 표(2026 → 2027, 증감), 대상별 바로가기(어르신/장애인/아이/저소득/회사), 각 계산기 링크. 표의 모든 숫자는 lib/calc/data 에서 불러온다.
5. "연말정산 장애인·부양가족 공제 체크" 도구(/calc/year-end-disability/ 등 01의 결과에 맞는 URL):
   - 일반 연말정산 계산기를 만들지 마라. 범위: 장애인 공제 대상 여부(장애인복지법상 장애인, 상이자, 항시 치료를 요하는 중증환자 등), 부양가족 요건(나이·소득), 장애인 전용 보장성보험·의료비 공제 체크리스트, 필요 서류(장애인증명서 등).
   - 금액·요건은 국세청 자료로만. 결과는 "공제 대상 가능성 + 챙길 서류 목록"이다.
6. 내부 링크: 기존 /tips/ 글 중 관련 글에서 새 계산기로 링크, 계산기에서 관련 글 2~3개로 링크.
7. 사이트맵에 추가(한 번에 20개 이하), GA4 이벤트(calc_start, calc_complete{calc_id, result_band}, next_action_click) 연결.
8. 빌드 후 각 페이지 HTML에서 8개 항목 존재 여부를 검사하는 스크립트(scripts/check-page-quality.mjs)를 만들어 돌리고 결과 표를 보고하라.
```
