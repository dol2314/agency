# 프롬프트 01 — 키워드 검증 (콘텐츠 우선순위 확정)

## 목표
기획안 3-2절의 후보 점수 중 "수요"를 실제 검색량으로 바꿔 클러스터 A·B·C의 페이지 우선순위를 확정한다.

## 운영자 작업 (이 프롬프트 실행 전)
1. 네이버 검색광고(searchad.naver.com) → 도구 → 키워드 도구에서 아래 씨앗 키워드를 넣고 연관 키워드를 **엑셀로 내보내기**. 파일을 `docs/keywords/naver-YYYYMMDD.xlsx`(또는 .csv)로 저장.
   - 씨앗: 기준중위소득, 중위소득 계산기, 기초생활수급자 조건, 기초연금 모의계산, 기초연금 수급자격, 장애인연금, 생계급여, 주거급여, 실업급여 계산기, 장애인 고용부담금, 장애인 고용장려금, 장애인 의무고용, 근로장려금 계산기, 자녀장려금, 연말정산 장애인공제, 문화누리카드, 에너지바우처
2. 가능하면 구글 키워드 플래너에서도 같은 씨앗으로 내보내기 → `docs/keywords/google-YYYYMMDD.csv`.
3. 서치콘솔에 데이터가 있으면 "실적 → 검색어" 최근 3개월 내보내기 → `docs/keywords/gsc-YYYYMMDD.csv`.

## Claude Code에게
```
docs/plan/README.md의 3장(콘텐츠 선정)을 읽어라. 그다음 docs/keywords/ 폴더의 키워드 파일을 모두 읽어 분석하라.

1. 키워드를 클러스터 A(2027 복지 자격·금액), B(장애인 고용), C(상반기 시즌: 근로장려금·문화누리·에너지바우처), 기타로 분류하라.
2. 각 키워드에 대해: 월간 검색량(PC+모바일, 네이버/구글 분리), 모바일 비중, 경쟁도, 그리고 "검색 의도"(계산/자격확인/신청방법/금액조회/기타)를 표로 만든다.
3. 기존 사이트 URL(sitemap.xml 또는 app/ 라우트)과 키워드를 짝지어 "이미 있는 페이지가 받을 키워드"와 "새 페이지가 필요한 키워드"를 나눈다.
4. 새 페이지 후보마다 점수 = (월 검색량 로그값) × (의도가 '계산/자격확인'이면 1.5) × (경쟁도 낮음 1.2 / 중간 1.0 / 높음 0.7) 를 계산해 상위 20개를 우선순위로 정렬한다.
5. 같은 의도의 키워드는 한 페이지로 묶어라(키워드마다 페이지를 만들지 않는다).
6. 결과를 docs/keywords/priority.md 로 저장: (a) 클러스터별 요약, (b) 페이지 단위 우선순위 표(URL 제안, 대표 키워드, 묶인 키워드, 합계 검색량, 점수), (c) 기획안 3-2절 점수와 달라진 점.

검색량 파일이 없으면 분석하지 말고 운영자 작업 1~3을 다시 안내하고 멈춰라. 검색량을 추측해서 채우지 마라.
```

## 완료 조건

- 클러스터 B(장애인 고용)의 합계 검색량이 표에 있다 → 05번 진행 여부 판단 근거.
